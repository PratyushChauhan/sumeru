# Agent rules

- Implement features in as few lines of code as possible.
- Bonus points if adding a feature reduces total lines of code.
- Keep UI consistent across the board.
- Use Doc strings with specified inputs and outputs for functions.
- Keep the docs updated.
- Add tests where required and keep them updated.
- "dev" is the working branch, main is the production branch.
- PRs that ship a feature or change behavior/state must show it: screenshots and/or a short screen recording of the main flow plus every state touched (empty, loading, error, success, flag/route variants). Backend-only changes: a command + response screenshot or a ~10s clip that reproduces it. Pure docs/chore PRs are exempt. Put media in the PR body; never commit large videos.
- If a shot doesn't make the change obvious, annotate it: outline what changed and label the state (before/after, rest/hover, empty/error, desktop/narrow, or a measured size). Annotated images go in the PR body, not the repo. Skip annotation when the shot is already clear.
